GITHUB · 5분 설명서

브랜치가 부딪히면
무슨 일이 일어날까?

그림 6장으로 '충돌(conflict)'을 처음부터 끝까지 따라가 봐요.

main 브랜치 feature 브랜치

STEP 01 · 시작

모두 같은 길을 걷고 있어요

처음엔 나도, 동료도 같은 코드(main)를 보고 있어요.

STEP 02 · 갈라짐

나는 다른 길로 갈라져요

새 기능을 만들려고 feature 브랜치를 따로 파요. 이제 두 갈래 길이 생겼어요.

STEP 03 · 같은 곳을 수정

main · style.css 
color: blue;
feature · style.css 
color: orange;

같은 줄을, 다르게 고쳤어요

나와 동료가 같은 파일, 같은 줄을 서로 다른 값으로 바꿔버렸어요. Git은 아직 이 사실을 몰라요.

STEP 04 · 충돌 발생

합치려다 그대로 부딪혔어요

두 길을 하나로 합치려는 순간, Git이 멈춰요. "어느 쪽을 남겨야 할지 나는 몰라요" — 이게 바로 충돌(conflict)이에요.

style.css 
<<<<<<< HEAD
color: blue;
=======
color: orange;
>>>>>>> feature

STEP 05 · 직접 정리

정리 전 
<<<<<<< HEAD
color: blue;
=======
color: orange;
>>>>>>> feature
→
정리 후 
color: blue;

내가 직접 골라줘요

표시선(<<<<<<<, =======, >>>>>>>)를 지우고, 남길 코드 한 줄만 남겨요.

STEP 06 · 완료

다시 하나의 길이 됐어요

Git에게 "다 골랐어"라고 알려주면 끝이에요. 두 길이 다시 하나로 이어져요.

git add style.css
git commit

기억할 3가지

  1. git status지금 어떤 파일이 충돌 중인지 확인해요.
  2. git add <파일명>내가 직접 정리했다고 알려줘요.
  3. git commit정리한 내용으로 합치기를 마무리해요.
